# Articles CMS

## One-time setup (manual)

1. In the dedicated Planned by Jay Supabase project, review and run **`supabase/migrations/20261025_articles_cms.sql`** once in SQL Editor as database owner, then **`supabase/migrations/20261027_article_placement.sql`** before deploying the placement controls. Existing installations need only the placement migration. The original setup creates four tables (`articles`, `article_categories`, `article_tags`, `article_tag_links`), their RLS/functions and the public **article-images** bucket. It seeds only the default Travel advice category, never sample articles. Do not rerun the original setup or restore the abandoned CMS. Nothing was applied automatically.
2. In **Authentication > Users**, reuse the confirmed `jay@plannedbyjay.com` account if present; otherwise create that exact user manually with a password and confirmed email. Do not use invitations or public registration. Disable public signups in the Auth provider settings. Do not share the password in chat. Existing project email/SMTP settings are not changed by this implementation. Password/account recovery is managed through Supabase's supported owner controls, not a new app authentication system.
3. Configure **SUPABASE_URL**, **SUPABASE_PUBLISHABLE_KEY** (`sb_publishable_...`) and public canonical **SITE_URL**. Existing local/production secrets were not modified. No service-role/secret database key, email provider, feature flag or publication approval is needed. Use `npm run dev` locally; production authentication requires HTTPS for Secure cookies. Set the same variables in the owner-authorised deployment's environment. The Supabase host is also used for Next Image allowlisting at build time.
4. After the separately authorised release, sign in at `/admin/login`. Only the confirmed business account can access article writes/uploads, enforced on server and database. Auth uses HttpOnly, SameSite=Lax cookies (Secure in production); the admin-only proxy refreshes Supabase sessions. Supabase's session/cookie lifecycle applies; no custom login token system is added.

## Publish the first article

**Admin > Articles > New Article.** Enter a title, select or create a category inline, and paste/write in the visual body. Use the toolbar for headings, bold, italic, lists, links, quotation and undo/redo. Paste HTML from Word/ChatGPT retains supported structure, including basic tables and header cells; unsafe elements/attributes are stripped. Use the Table dropdown to insert a table, add/remove rows and columns, toggle header cells or remove a table. Edit text directly in its cells. Public tables scroll horizontally on narrow screens. Ordinary underlined text displays without an underline publicly; links retain theirs. No Markdown or HTML typing is required.

The short URL is suggested deterministically; expand **Article URL** to correct it. A duplicate URL produces a useful error: choose another before saving. Once first published the URL is locked, including after unpublishing. Changing its title does not break its shared link. One default Travel advice category is used if none is chosen. Category names and tags reuse case-insensitive matches. Enter each tag and press Enter (or Add tag).

Photographs are optional. Choose a previously uploaded image or upload a JPG/PNG/WebP up to **4 MB**; uploads are decoded, rotated, resized to at most 2000px and stripped of metadata, then stored as WebP. Review the suggested image description. Selecting, replacing or removing a photograph does not reset the article. The bucket is public and intended only for permitted public photographs, never private/customer documents. Shared original files are retained when an article or image association is removed, so they remain reusable; this is not a separate asset-management system.

**Save Draft** keeps unfinished work private (and returns a published article to draft). **Preview** shows unsaved content in the real article layout without saving or publishing; its endpoint requires admin authentication. **Publish** requires only title and meaningful article text. Author defaults to Jay. Created/updated dates are automatic. Optional expiry keeps an article public through the selected date in UK time; afterwards it remains editable privately. No scheduler is used. A past expiry is explained in save feedback.

Successful publication appears automatically under Travel Advice, its individual URL and the sitemap. **Feature on Homepage** independently selects homepage previews; **Pin to Top of Travel Advice** puts an article before unpinned articles, with newest first within each group. Both are off by default and respect publication/expiry. Published articles show **Published** and **Save Changes**; drafts retain **Publish**. A repeated leading body heading matching the page title is omitted on display without changing the saved body or later section headings. Metadata, excerpt, canonical URL, Open Graph/social image and Article structured data derive from current content. There are no manual SEO fields and no ranking guarantee. Production indexing stays off until Jay sets `SITE_INDEXABLE=true` for the production deployment; publication alone is not search-indexing approval.

The dashboard supports title search, paging, Edit, Copy Link, Return to Draft and confirmed deletion. Public reads always use an anonymous client and expiry-aware RLS, even for a signed-in owner. Draft/expired/deleted articles return 404. Saves/unpublishing/deletion invalidate the existing public routes; provider reads are uncached. Category/tag public reads cannot expose draft-only classifications.

## Work preservation and limits

Save regularly: no background autosave or browser storage. Inline categories, tags, photographs and failed requests retain the mounted editor and current text. Leaving with unsaved changes raises a browser warning. Save operations temporarily lock editing, and a version check rejects overwrites from another tab without creating revision-history tables. Copy your work before reloading after a conflict.

The supported format intentionally excludes scripts, embedded media, arbitrary styles and document uploads. Photos are optional; image description is editable. Published URLs cannot be renamed through the editor. Hosted Auth/storage/database setup and a real sign-in/upload/publication need owner verification after applying the migration; local fixtures are not evidence of a live login or hosted publish. No live test article, hosted setting, deployment or push is performed automatically.

Validation: all 21 automated tests, ESLint, TypeScript and the production build passed. Tests apply the actual migration to an isolated in-memory PostgreSQL fixture and exercise the real visual editor in JSDOM; they do not create hosted data. A temporary local production server confirmed login 200, signed-out admin redirects, unauthenticated write/preview 401 and cross-origin 403, then was stopped. The article detail HTTP check returned 500 with the hosted article data source unavailable before manual setup; successful hosted publication/404 behaviour still needs verification after setup (fixture coverage passed). No browser was available, so desktop/mobile visual checks were not performed. The enquiry form remains disabled; suppliers, offers, bookings and social posting are outside this module.


Article editor polish: choose Paragraph, Heading or Subheading from the text-style dropdown; the compact formatting buttons have tooltips and accessible labels. Existing paste and keyboard shortcuts are retained. Beneath the title, **Short preview / introduction (optional)** accepts up to 200 characters (aim for 150-200). It supplies public article cards and SEO/social descriptions; leaving it blank generates a body-text preview without headings, preferring complete sentences. Existing stored previews remain available. No SQL migration is required: the existing excerpt column is reused.

Save Draft, Publish and Unpublish temporarily disable editing and show progress beside the controls. Results remain there until the next edit/action. Successful publication provides View Article and Copy Link using the saved slug; expired articles instead explain why they are not public. Failed saves keep the current editor content. Unpublish saves the current article as a private draft. No deployment or hosted database changes are performed by this update.

Polish validation: 21 automated tests passed (the public-route fixture used a temporary WebSocket shim for the installed Node 20 runtime). ESLint, TypeScript and production build passed. The project requires Node 22.13+; obtaining Node 22 locally was blocked by registry certificate verification. No browser connection was available for visual checks, and no hosted writes were tested.
